# Веб-панели (mini apps) в пилотном комплекте

Памятка для того, кто собирает установщик. Описывает, что такое панель, что
нужно сделать установщику, чем проверить результат и как выглядят отказы.

Первая панель — **«Сделки»** (демонстрационная CRM). Вторая, «Конкурентный
лист», ставится теми же шагами с другим именем и портом.

## Что такое панель и почему это не просто сайт

Панель — отдельный контейнер с nginx, отдающий одностраничное приложение.
Вольт показывает её **в кадре рядом с чатом**, и агент работает с ней через
объявленные ею инструменты: человек и агент меняют одни и те же данные, а
каждое действие попадает в общий журнал.

Из этого следуют три требования, которые и отличают панель от обычного сайта.
Все три уже зашиты в образ, трогать их не нужно — но нужно **не сломать** их
по дороге:

| Заголовок | Значение | Зачем |
| --- | --- | --- |
| `Content-Security-Policy` | `frame-ancestors 'self' <адрес Вольта>` | кто имеет право показывать панель в кадре |
| `Cross-Origin-Embedder-Policy` | `credentialless` | без него кадр остаётся пустым |
| `Cross-Origin-Resource-Policy` | `cross-origin` | то же самое |

⚠ Отказывают они одинаково и молча: **пустой прямоугольник и ни одной записи в
консоли**. Если панель не нарисовалась — проверяйте эти три заголовка раньше
всего остального.

⚠ TLS-вход обязан пропускать заголовки панели **не трогая**. В nginx директива
`add_header` внутри `location` отменяет все унаследованные заголовки — поэтому в
блоке панели не должно быть ни одного своего `add_header`. Это то же правило,
что уже записано в шапке `tls-nginx.conf.template`.

## Предварительное условие: бэкенд должен знать про панели

Маршрут `/v1/mini-apps` появился в Вольте позже, чем собран пилотный образ
бэкенда. **Пока бэкенд не пересобран, панели не появятся ни при каком клиенте.**

Проверка одной командой (изнутри машины пилота):

```sh
curl -s -o /dev/null -w '%{http_code}\n' https://<адрес>/v1/mini-apps
```

- `401` — маршрут есть, просто нужен вход. Это норма, можно ставить панели.
- `404` — **маршрута нет**: бэкенд старый, установщику нужен свежий образ
  `volt-backend:pilot`, собранный из `master`.

Клиент на `404` ругаться не будет: с октября он считает это «панелей в этой
установке нет» и молчит. Поэтому отсутствие ошибок в консоли — не доказательство
того, что всё в порядке; проверяйте кодом ответа.

## Что поставляется

| Что | Откуда | Размер |
| --- | --- | --- |
| `volt-panel-crm.tar.gz` | `docker save volt-panel-crm:pilot`, собирается у нас | ≈ 25 МБ |
| строка `MINI_APPS` | образец ниже, секрет генерирует установщик | — |

Образ самодостаточен: внутри nginx и собранная панель, наружу ходить ей незачем.

## Что делает установщик

### 1. Загрузить образ

```sh
docker load -i volt-panel-crm.tar.gz
```

### 2. Поднять контейнер

Порт наружу **не публикуем**: панель должна быть доступна только через
TLS-вход, как и всё остальное в пилоте. Фрагмент для файла композиции —
`docker-compose.miniapps.yml` рядом с этой памяткой.

`VOLT_ORIGIN` — адрес самого Вольта, тот же, что у клиента. Это ровно тот
адрес, которому разрешено показывать панель в кадре.

### 3. Дать панели свой порт на существующем TLS-входе

**Второй nginx не нужен.** Это тот же терминатор `tls`, которому добавляется
один слушатель и одна строка портов:

```
ports:
  - "${VOLT_TLS_HTTP_PORT:-80}:80"
  - "${VOLT_TLS_HTTPS_PORT:-443}:443"
  - "127.0.0.1:${VOLT_TLS_KEYCLOAK_ADMIN_PORT:-8445}:8445"
  - "${VOLT_MINIAPP_CRM_PORT:-5191}:5191"      # ← добавить
```

Сам блок — `tls-miniapps.conf.template` рядом; его содержимое вклеивается в
`conf/nginx/tls-nginx.conf.template` как ещё один `server { … }`.

Панель должна жить на **отдельном происхождении**, а не по пути внутри адреса
Вольта. Происхождение — это схема, имя и порт; отдельный порт даёт разделение,
**не требуя ни нового имени в сертификате, ни записи в DNS** — проверено на
пилотном сертификате: он выписан на `CN=backend.volt.oktaplus.ru` с именами
`backend.volt.oktaplus.ru, localhost, 127.0.0.1, 192.168.88.243`, и порт в лист
не входит. Путь (`/apps/crm/`) разделения не даёт: панель оказалась бы тем же
происхождением, что и само приложение, и проверка происхождения в протоколе
панели потеряла бы смысл.

### 4. Дописать запись в `.env` бэкенда

```
MINI_APPS={"crm":{"name":"Сделки","description":"Демо-CRM: список, канбан, карточка сделки.","icon":"table","origin":"https://<адрес>:5191","secret":"<32+ случайных символа>"}}
```

- `icon` — из разрешённого списка: `app-window`, `bar-chart`, `file-search`,
  `line-chart`, `route`, `stethoscope`, `table`. Неизвестное имя молча станет
  обычным окном.
- `url` необязателен и по умолчанию равен `origin`.
- `secret` генерирует установщик на каждую установку:
  `openssl rand -base64 32`. В git он не попадает никогда.
- Несколько панелей — один объект с несколькими ключами, не несколько
  переменных.

### 5. Перезапустить бэкенд

```sh
docker compose restart backend
```

⚠ Настройки читаются **один раз за запуск процесса**. Без перезапуска запись не
подхватится, и это самая частая причина «панель не появилась».

## Что уже проверено на живом стенде

Схему прогнали 15 октября 2026 на работающем пилоте, не меняя ни одного файла
комплекта (отдельный терминатор с тем же сертификатом только на чтение —
времянка ради проверки, в поставке её нет):

```
GET https://backend.volt.oktaplus.ru:5193/        →  200
Content-Security-Policy: frame-ancestors 'self' https://backend.volt.oktaplus.ru
Cross-Origin-Embedder-Policy: credentialless
Cross-Origin-Resource-Policy: cross-origin
Cache-Control: no-store
```

То есть: сертификат порт покрывает, три заголовка проходят через прокси
нетронутыми, происхождение у панели своё, разметка не кэшируется.

⚠ `curl` на Windows откажется проверять частный CA — «revocation status is
unknown», у такого CA нет списка отзыва. Это особенность schannel, а не
сертификата: в приёмке пользуйтесь `curl -k`, а доверие проверяйте открытием
в браузере, где CA уже установлен.

## Приёмка

1. `curl -s -o /dev/null -w '%{http_code}' https://<адрес>:5191/` → `200`.
2. `curl -sI https://<адрес>:5191/ | grep -i -E 'frame-ancestors|embedder|resource-policy'`
   → три заголовка на месте.
3. `curl -s -o /dev/null -w '%{http_code}' https://<адрес>/v1/mini-apps` → `401`, не `404`.
4. Войти в Вольт: в боковой панели под «Приложения» появились «Сделки» с иконкой
   таблицы.
5. Открыть — панель рисуется в теме клиента; переключить тему клиента, панель
   переезжает вместе с ним.
6. В чате встроенному агенту: «покажи сделки на стадии переговоров». Агент
   вызывает инструмент панели, Вольт спрашивает подтверждение, после согласия
   список на экране меняется, а в журнале появляется запись с пометкой «Агент».

⚠ Пункт 6 — только **встроенный** агент. Удалённому агенту шлюза Вольт на каждый
новый сеанс отправляет пустой список серверов инструментов, то есть про панель он
не знает вовсе. Это известное ограничение, а не дефект установки.

## Если не работает

| Что видно | Что это значит |
| --- | --- |
| Панели нет в боковой панели | бэкенд не перезапущен; либо окно уже окна, при котором запись скрыта |
| `/v1/mini-apps` отдаёт `404` | старый образ бэкенда, маршрута нет — панели не заработают |
| Кадр пустой, в консоли пусто | один из трёх заголовков встраивания потерян на TLS-входе |
| «Смешанное содержимое» в консоли | панель отдаётся по `http`, а клиент работает по `https` |
| Панель открылась, но агент её «не видит» | выбран агент шлюза, а не встроенный |
| Панель показывает старое после обновления | кэш браузера; разметка отдаётся с `no-store`, ссылки на ресурсы со штампом содержимого — значит, обновлён не тот образ |
