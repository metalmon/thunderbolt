# Разрешение имён на клиентских машинах (без DNS)

В закрытом контуре DNS нет, а подставить вместо имени IP-адрес нельзя: у
установленного клиента «Вольт» адрес бэкенда **вшит на этапе сборки** (одна
сборка на всех заказчиков), и сертификат выпущен на то же имя. Значит имя должно
разрешаться локально, на каждой клиентской машине.

Вшитый адрес текущей сборки — `https://backend.volt.oktaplus.ru/v1`.

## Что должно разрешаться

| Имя | Куда | Зачем |
|---|---|---|
| `backend.volt.oktaplus.ru` | IP хоста пилота | вшитый адрес бэкенда: вход, синхронизация, прокси моделей |
| то же имя, порт 8444 | тот же IP | Keycloak (вход через OIDC) |
| имя из листа voltd, порт 8443 | IP хоста пилота | `wss://…/acp` — агенты |

Если лист voltd выпущен на то же имя, записи нужны одна. Если на другое — две.

**Имя в сертификате и вшитое имя должны совпадать.** Лист для `tls`-службы
выпускается на `backend.volt.oktaplus.ru` (`certs/gen-certs`), и это же имя
идёт в `VOLT_TLS_SERVER_NAME`, `PUBLIC_URL` и `KEYCLOAK_PUBLIC_URL`
(`scripts/gen-secrets … --tls`). Лист на другое имя = клиент не откроет бэкенд, и
починить это на объекте нечем, кроме перевыпуска сертификата.

## Как прописать

На каждой клиентской машине, один раз, рядом с установкой корня CA
(`certs/install-ca.*` — нужно и то и другое: имя должно разрешаться **и**
сертификат должен быть доверенным).

Windows, из консоли с правами администратора:

```powershell
scripts\install-hosts.ps1 -Ip 10.20.30.40 -Names backend.volt.oktaplus.ru
```

Linux (Astra / RED OS / Ubuntu), от root:

```bash
sudo scripts/install-hosts.sh 10.20.30.40 backend.volt.oktaplus.ru
```

Оба скрипта:

- перезаписывают свою прошлую запись и любую строку с тем же именем, поэтому
  повторный запуск после смены IP не оставляет дубля (а дубль в hosts выигрывает
  или проигрывает в зависимости от порядка строк — худший вид неисправности для
  отладки на чужой машине);
- сбрасывают кэш резолвера;
- печатают, во что имя разрешилось фактически;
- умеют убрать запись (`-Remove` / `--remove`).

Несколько имён — через запятую (`-Names a,b`) или списком аргументов
(`install-hosts.sh <ip> a b`).

## Если клиент уже запущен

Перезапустить «Вольт». WebView2 и Chromium кэшируют разрешение имени на процесс,
так что правка hosts на работающем клиенте ничего не меняет.

## Как проверить, что дело в имени

- `https://backend.volt.oktaplus.ru` не открывается в браузере на клиентской
  машине → запись не прописана или прописана на другой IP;
- открывается, но с предупреждением о сертификате → корень CA не установлен
  (`certs/install-ca.*`);
- открывается, но вход не завершается → см. `KEYCLOAK_PUBLIC_URL` и редиректы
  реалма (их переписывает `scripts/gen-secrets`, см. `README.md`);
- клиент показывает старый адрес → `cloudUrl` сохранён в `localStorage` и
  переживает обновление, его надо сбросить (см. `README.md`).
